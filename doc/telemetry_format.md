# 航電遙測通訊格式規範 (Telemetry Format Specification)

本文件定義火箭航電板與地面站 (Ground Side) 之間，透過 LoRa 傳輸數據的 ASCII 通訊格式。

> **權威來源**：發送端格式字串寫死在 `firmware-rocket/Core/Src/main.c` 的
> `lora_pkt` snprintf；C 語言版的契約在 `rocket-system/shared/protocol.h`；
> 解析器在 `src/core/models.py` 的 `SensorData.from_new_format()`。
> 三者不一致時，**以 main.c 為準**。
>
> ⚠️ **2026-07-30 大幅修訂**。本文件此前的欄位表與實際封包有多處出入，其中
> `ST` 的狀態對照表錯得最危險（把「正在放傘」標成「點火」）。修訂內容列於文末。

## 通訊協議特點

1. **分隔字元**：每個數據欄位之間使用**一個半形空格**分隔，Key 緊貼數值（**沒有 `=`**）。
2. **結束字元**：整行以 `\r\n` (CRLF) 結束。
3. **兩種長度**：GPS 定位成功時尾端多 `LAT`/`LON` 兩欄，未定位時沒有。這是唯一的變體。

## 遙測數據格式範例

### 無 GPS 定位
```text
T28386 SQ42 AX+0.007 AY+0.026 AZ+0.978 GX+6.09 GY-1.05 GZ-2.80 P997.92 RH-0.1 KH-0.1 VZ+0.00 GA0.98 ST:0 MOD:F GPS:0,0 C:0 VF8.12 VA7.98
```

### GPS 定位成功
```text
T28386 SQ42 AX+0.007 AY+0.026 AZ+0.978 GX+6.09 GY-1.05 GZ-2.80 P997.92 RH-0.1 KH-0.1 VZ+0.00 GA0.98 ST:0 MOD:F GPS:1,8 C:0 VF8.12 VA7.98 LAT+22.17483 LON+120.89272
```

## 欄位詳細定義

| 欄位 Key | 型態 | 說明 | 範例 | C `sprintf` |
| :--- | :--- | :--- | :--- | :--- |
| **T** | `uint32` | 上電後時間 (ms) | `T28386` | `"T%lu"` |
| **SQ** | `uint32` | **封包序號**，遞增。用來算掉包率；數值倒退 = 火箭端重開機 | `SQ42` | `"SQ%lu"` |
| **AX/AY/AZ** | `float` | 三軸加速度 (g，機體座標) | `AX+0.007` | `"AX%+0.3f"` |
| **GX/GY/GZ** | `float` | 三軸角速度 (deg/s，機體座標) | `GX+6.09` | `"GX%+0.2f"` |
| **P** | `float` | Kalman 平滑後氣壓 (hPa) | `P997.92` | `"P%.2f"` |
| **RH** | `float` | 相對起飛點高度 (m)。**裸氣壓，不經 KF** — 開傘條件 A 用的就是它 | `RH-0.1` | `"RH%.1f"` |
| **KH** | `float` | KF2 融合高度 (m)，IMU 積分 + 氣壓修正 | `KH-0.1` | `"KH%.1f"` |
| **VZ** | `float` | KF2 垂直速度 (m/s) — 開傘條件 B 用的就是它 | `VZ+0.00` | `"VZ%+0.2f"` |
| **GA** | `float` | 合加速度 \|a\| (g) | `GA0.98` | `"GA%.2f"` |
| **ST** | `int` | 飛行狀態，**只有 0~4**，見下表 | `ST:0` | `"ST:%d"` |
| **MOD** | `hex` | 模組存活旗標，1 個十六進位字元，見下表 | `MOD:F` | `"MOD:%X"` |
| **GPS** | `int,int` | 定位狀態,衛星數。未定位時固定 `GPS:0,0` | `GPS:1,8` | `"GPS:1,%u"` |
| **C** | `hex` | **開傘條件狀態**，1 個十六進位字元，見下表 | `C:0` | `"C:%X"` |
| **VF** | `float` | 保險絲後端電壓 (V)。`-1.00` = ADC 不可用 | `VF8.12` | `"VF%.2f"` |
| **VA** | `float` | arming 開關後端電壓 (V)。`-1.00` = ADC 不可用 | `VA7.98` | `"VA%.2f"` |
| **LAT/LON** | `float` | (選填) GPS 座標，只在 `GPS:1` 時出現 | `LAT+22.17483` | `"LAT%+0.5f"` |

### ST — 飛行狀態

| 值 | 名稱 | 說明 |
| :-- | :--- | :--- |
| `0` | IDLE | 地面靜置，等待離架 |
| `1` | LAUNCHED | 離架後，監視高度與時間 |
| `2` | **DEPLOYING** | **開傘訊號輸出中**（`DEPLOY_PULSE_MS` = 1 秒） |
| `3` | DEPLOYED | 開傘完成，等待落地 |
| `4` | LANDED | 落地確認，低功耗記錄模式（終端狀態） |

> 🔴 **本文件此前記載的 12 狀態版（`2=IGNITION`、`6=APOGEE`、`7=PARACHUTE_DEPLOY`…）
> 從未實作。**照那份判讀會把 `ST:2` 讀成「點火」——實際是「正在放傘」。
> 12 狀態方案若要實作，火箭端的 `FlightState_t` 列舉必須先改（`main.c:292`）。

### MOD — 模組存活（1 = 正常）

| bit | 模組 | | 常見值 | 意義 |
| :-- | :--- | :-- | :--- | :--- |
| 3 | 氣壓計 BMP585 | | **`F`** | 四個全正常 |
| 2 | IMU | | **`7`** | 🔴 氣壓計死 |
| 1 | LoRa | | **`B`** | 🔴 IMU 死 |
| 0 | SD 卡 | | `E` | SD 卡死 |

> 本文件此前寫「皆正常為 `E` / 二進制 1110」，那是錯的——`E` 代表 SD 卡死。

### C — 開傘條件狀態

| bit | 欄位 | 說明 |
| :-- | :--- | :--- |
| 3 | `cond_A` | 氣壓高度低於峰值 10m（峰值須先 ≥ 20m） |
| 2 | `cond_A_eff` | 套用感測器故障降級後，實際採用的 A |
| 1 | `cond_B` | KF2 垂直速度 < −0.5 m/s 持續 1.5 秒 |
| 0 | `cond_B_eff` | 套用降級後，實際採用的 B |

開傘 = `(A_eff ∧ B_eff) ∨ C`，其中 C 是離架偵測後 18 秒的純計時備援（不在本欄位中）。

**降級規則不對稱**（2026-07-30 起）：

| 死掉的 | 效果 | 理由 |
| :--- | :--- | :--- |
| **IMU** | `B_eff = 1`，由 `cond_A` 單獨守門 | 純氣壓、無積分無漂移，可信 |
| **氣壓計** | `A_eff = 0`，主路徑關閉，退到 18s 備援 | `kf2_v` 靠氣壓修正，氣壓一死它是漂移量不是量測值 |
| 兩者皆死 | 兩個 eff 都是 0，只剩備援 | 避免用死值立即觸發 |

**判讀速查**：`C:0` 正常飛行中 ／ `C:1` IMU 死 ／ `C:F` 兩條件皆成立（開傘）

> 本文件此前把此欄稱為「發火迴圈導通狀態」，那是錯的——它與火工品導通無關。
> 火工品的電氣狀態在 `VF` / `VA` 兩欄。

## 🔴 截斷幀處理

**缺 `ST` / `MOD` / `GA` 任一欄 → 整幀丟棄。**

這三欄位於封包後段，任一缺席即代表尾巴被 RF 切掉。

> 本文件此前寫「即便欄位缺失，解析器仍能正確還原剩餘有效數據，不會造成整幀失效」
> ——那個行為已在 2026-07-28 移除，因為它是危險的：
> `T12345 AX+0.01` 會被當成完整資料接受，產生高度 0、速度 0、**ST 0** 的假紀錄。
> `ST=0` 最致命：它會重設地面站的 stage 邊緣偵測基準，下一筆真封包的 `ST:2`
> 就成了「0→2 的轉入」，在沒有新證據的情況下確認一道待確認的開傘指令
> ——正是下行確認機制要防的假陽性。

同理：**宣稱 `GPS:1` 卻缺 `LAT`/`LON` 的幀降級為 `NO_FIX`**。舊碼會靜默套用
預設座標 (25.0, 121.5) — 台北 — 並在地圖上畫成有效定位。落海搜救時那是災難性誤導。

## 火箭端事件訊息 (MSG)

除高頻遙測外，重要事件會以純文字訊息送出：

```text
MSG <LEVEL> <CONTENT>\r\n
```

| 欄位 | 值 | 說明 |
| :--- | :--- | :--- |
| Header | `MSG` | 固定標頭，表示此幀為事件訊息而非遙測 |
| Level | `INFO` / `WARN` / `ERROR` / `SUCCESS` | 訊息等級 |
| Content | `string` | 內容（地面站 `maxsplit=2`，可含任意空格） |

### 地面站會據以動作的字串

| 字串 | 地面站行為 |
| :--- | :--- |
| `Parachute deployed successfully` | 確認 `/dpl` 指令送達 |
| `Airbag inflation started` | 確認 `/abg` 指令送達 |
| `already deployed` | 視為「傘已開」的證據，**不是**失敗 |
| `REJECT <dpl\|abg\|...>` | 對應指令被閘門拒收 |
| `MANUAL ARMED (%ds)` / `MANUAL SAFE` / `ARM expired` | 更新 ARM 狀態顯示 |

> ⚠️ **自動開傘的訊息刻意不含 `successfully`**：
> `Parachute deployed (auto A+B pk=... now=... vz=...)` 與
> `Parachute deployed (backup timer T>18s pk=... now=...)`。
> 自動開傘沒有待確認的指令，不該觸發下行確認機制。

其餘 MSG 只顯示在 log，不觸發任何自動動作。

## 地面站對接說明

1. **純 ASCII 直解析**（舊版 JSON 格式已完全廢棄）。
2. **3D 姿態估算**：地面站用重力加速度估算 Roll 與 Pitch，驅動 3D 立方體與線圖。
3. **異常警報**：不符格式的資料在終端 log 印紅色警告。
4. **掉包率**：以 `SQ` 序號的連續性計算，序號倒退視為火箭端重開機。
